## 第一次：短录音

1. 启动官方 Flutter example，授予实际请求的权限。
2. Scan，选择名称包含 Clip 的设备，处理配对提示。
3. Version / Status：记录固件版本、设备状态、电量。
4. Record：录制约 10 秒人声，Stop：保存 session ID。
5. List：确认录音文件存在。
6. BLE DL：等待完整的完成事件，记录文件数量、大小和校验结果；日志仅出现开始下载不算成功。
7. 在相同 session 上运行 WiFi sync，接受设备热点连接；热点无互联网是预期现象。
8. 对比两种传输获取的音频分片内容或哈希；session.json 可能因同步进度变化，不要求全部元数据逐字节相同。
9. 使用参考转换工具，将完整的原始 Opus 帧封装为 Ogg 或解码为 WAV；参数依据 session.json。
10. 先在电脑确认可播放、时长和声音正常；手机播放需复用业务 App 解码实现或后续补充播放功能，最小示例没有播放器。

参考转换代码位于：
- `upstream/applications/clip/tests/clip/codec.py`
- `upstream/applications/clip/tests/tools/decode_opus.py`
- `upstream/mobile/app/lib/src/core/audio/raw_opus_decoder.dart`

## 第二次：可靠性

- [ ] 多次断开、重连后仍可获取状态。
- [ ] 更长录音完整下载并播放，记录耗时和文件大小，不预设速率。
- [ ] 取消和重试后不会将残缺文件标为成功。
- [ ] 锁屏 / 切后台后记录实际行为，验证可恢复，不默认后台持续运行。
- [ ] Wi-Fi 下载结束后正常联网；失败路径也能退出临时网络。
- [ ] 后续业务 App 使用长期存储目录，重启后能找到录音。

首次调试保留设备原始录音。OTA 单独验证，只使用已确认适配该硬件与固件组合的官方包；不是短录音验证的前置条件。
