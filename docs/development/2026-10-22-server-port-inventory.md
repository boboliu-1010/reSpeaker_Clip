## 9527 是哪个 Server

活跃进程属于 `roger`，PID `27560`，入口 `/home/roger/clip-receiver/app/run_receiver.py`，参数 `--port 9527`。这与本仓库 [Clip 接收端部署说明](../../tools/https_poc/deploy/README.md) 中记录的 `https://100.58.19.213:9527` 对应。

对照仓库协议实现，该入口用于 `/v1/devices/.../recordings/...` 与 `/v2/devices/.../recordings/...` 的原始录音接收、检查点查询和续传，不是 Boa 的 `/api/audio` 分片音频库。bobo 无权读取 Roger 的部署目录，因此这里没有声称逐文件复核了远端接收端代码；结论依据实际进程入口、HTTPS 响应与仓库部署记录。

此前的 18765/18766 连接失败不能推导成“服务器所有 HTTP 端口不可达”。**现在已经找到可达的 HTTPS 入口 9527，但桌面音频库尚未接入这个入口。**

## TLS 检查

- 不带任何正式凭据的 HTTPS 协议识别收到了 401，说明 9527 的网络与 HTTPS 响应可用；这一探测没有验证 CA 信任，不能当作正式安全连接验收。
- Mac 桌面同一 `StorageClient` 使用默认信任连接时失败：`CERTIFICATE_VERIFY_FAILED`。未关闭桌面客户端证书验证，没有将正式 Boa 令牌发给另一个服务。
- 服务端出示的证书 SAN 覆盖 `100.58.19.213`，到期时间为 **2026-10-25 08:37:10 UTC，即北京时间 16:37:10**；现有开发 CA 和证书续期需另行处理。

## 桌面端 HTTP 测速还需要什么

可在设计上复用 9527 的 HTTPS 入口，但需要明确按路径分流：

| 请求 | 应进入的服务 |
| --- | --- |
| 既有 Clip `/v1`、`/v2` 和健康接口 | 保留现有 Clip 接收端行为及设备凭据 |
| Boa `/api/audio/...` | 转发到 `127.0.0.1:18765`，由 Boa 独立校验自己的令牌 |

这只是路由建议，**本次没有修改 Roger 的服务、增加反向代理或实现原始录音入库桥接**。接入前还需给桌面客户端提供正确 CA 信任或受信任证书；不应仅把 App 地址改到 9527，也不能复用错误服务的 Bearer 令牌。由于当前 `/api/audio` 路径和证书信任尚未打通，桌面与 Server 的正式 HTTP 吞吐仍未测得。
