# Boa Voice 桌面版复审与 Beta 3 范围

日期：2026-10-21。基线：1.0.1-beta.2 / 54d6158。用户已确认本轮先补录音、文件管理、同步、Clip 状态展示四组。

## 目标与参考

面向个人录音、会议和访谈整理，把“录下来 → 找到 → 备份 → 回听/导出”做完整。保留自有 HTTP 存储，不引入官方账号依赖。

参考官方 [Clip 入门及 App 使用](https://wiki.seeedstudio.com/cn/respeaker_clip/)、[SDK 说明](https://github.com/Seeed-Studio/reSpeaker_Clip/blob/main/mobile/README.md) 与仓库现有手机业务模块。官方文档包含文件导出、重要标记、裁剪及 STT/LLM 分开配置；入门 Wiki 标注为草稿，硬件能力以代码、协议与真机结果为准。现有手机 AI 配置仓库调用独立后端接口，并不能直接套在当前纯文件存储 Server 上。

## 发现与本轮改动

| 项目 | Beta 2 缺口 | Beta 3 验收行为 |
| --- | --- | --- |
| 麦克风 | 只能默认输入，无信号指示，文件名为时间戳 | 选择输入设备、显示电平，停止后命名；未保存文件可恢复 |
| 文件 | 只有导入/播放，没有详情、重命名、导出和恢复 | 本地详情显示格式、时长、时间、大小和来源；改名、流式导出、回收与恢复 |
| 同步 | 手动上传也受自动开关限制；重试作用于全部任务；进度和错误不清楚 | 显式手动上传独立于自动开关，按项重试；任务列表显示进度、失败原因和等待状态 |
| Clip | GSTAT/版本只有原始 JSON | 设备名称、电量、充电、录音状态、时长、剩余空间、固件版本可读展示；缺失显示未知 |

## 数据与交互约束

- 兼容既有库及队列，不清空录音或服务器；本地展示名称可修改，文件仍按内容哈希保存。改名不悄悄改服务器名称。
- “移到回收站”只处理本地副本，保留服务器文件；本轮不提供永久删除。正在上传时保护相关文件，恢复后重新按设置备份。
- 手动上传是用户显式任务，关闭自动备份后仍可进行与重试；自动任务暂停。队列不写入凭据，认证错误提示不包含令牌。
- 导出经系统保存对话框选择目标，流式复制并校验；不将大文件整体载入 Dart 内存。需要 macOS 用户选择文件的读写权限。
- 未保存录音留在暂存目录，重启后提供恢复入口；无效/损坏暂存文件不会自动删除。强制终止造成的容器损坏不能保证恢复。
- Clip 展示按现有 GSTAT 字段和版本回应解析；不新增固件命令，不把缺少字段当成零，不把 UI 模拟当作硬件联调。
- 继续使用 Beta 版本号。未公证状态明确说明；打包扫描全部原生依赖，实际从 DMG 安装、启动与退出重开。先本地验收，用户确认后再上传。

## 后续方向

下一组独立能力：本地配置 Azure/兼容 API 的 STT 与 LLM，连接测试、异步任务、转写编辑、时间戳回听、摘要模板和结果导出。音频上传不自动触发模型计费。

硬件到货后：按官方/定制固件分别验收 BLE 文件列表与下载、Wi-Fi 同步、标记与 OTA，再决定接入范围。之后再评估裁剪、文件夹/标签、搜索转写、桌面更新通知与稳定签名公证。
